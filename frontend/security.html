LighterDeck

Sicurezza

Ultimo aggiornamento: 17 novembre 2026

In breve: su lighterdeck.xyz la tua API key resta nel tuo browser. Gli ordini vengono firmati lì con il firmatario ufficiale di Lighter e vanno direttamente a Lighter. Il server di LighterDeck non riceve mai la chiave e non tocca mai i tuoi fondi.

1. Dove resta la chiave

  • Solo nel tuo browser. Quando colleghi una API key, LighterDeck la verifica con Lighter direttamente dal browser e la tiene lì. Non viene inviata al server di LighterDeck né a nessun altro.
  • "Ricorda la chiave su questo browser". Se la casella è spuntata, la chiave è salvata nella memoria del browser per questo sito e ritrovi il collegamento quando torni. Se non è spuntata, resta solo finché la scheda è aperta. La memoria del browser non è cifrata: su un computer condiviso, o se non ti fidi del dispositivo, togli la spunta.
  • Scollegare la chiave da LighterDeck la cancella dal browser. Per renderla inutilizzabile ovunque, revocala dalla pagina API keys di Lighter.

2. Come vengono firmati gli ordini

  • LighterDeck usa il firmatario ufficiale di Lighter, lighter-go, compilato in WebAssembly senza modifiche. Gli ordini firmati vanno dal tuo browser all'API di Lighter.
  • Ogni firma usa un valore casuale nuovo (il nonce), generato con il generatore sicuro del browser. Se lo stesso ordine viene firmato due volte, le firme sono diverse.
  • La pagina esegue solo il codice di LighterDeck, servito da lighterdeck.xyz: una Content-Security-Policy blocca gli script di altri siti e permette collegamenti solo a LighterDeck e a Lighter. Anche se qualcuno riuscisse a inserire del codice nella pagina, non potrebbe mandare la chiave altrove.
  • Il codice di LighterDeck è open source: chiunque può controllare cosa fa con la chiave. Il firmatario è nella cartella frontend/signer/, con il commit di lighter-go da cui è compilato.
L'incidente del 16 novembre 2026. Le chiavi di un trader sono state ricavate dalle sue firme, perché il suo codice di firma, non ufficiale, riutilizzava i nonce. LighterDeck firma solo con il firmatario ufficiale, che genera ogni nonce in modo casuale e sicuro, e non era esposto a questo problema.

3. Creare una chiave con il wallet

  • Con "Crea una chiave con il wallet" la nuova chiave viene generata nel tuo browser. Il wallet firma soltanto il messaggio di Lighter che registra quella chiave sul tuo account ("Register Lighter Account").
  • LighterDeck legge l'indirizzo del wallet per trovare l'account, ma non vede mai la chiave privata o la frase di recupero del wallet. Non chiederà mai né l'una né l'altra: se qualcuno te le chiede a nome di LighterDeck, è una truffa.
  • Firma nel wallet solo messaggi che riconosci. Quello di Lighter termina con "Only sign this message for a trusted client!".

4. Cosa può fare una API key

Chi la ottiene può

  • fare trading sul tuo account, anche contro di te a prezzi sfavorevoli, soprattutto nei mercati poco liquidi;
  • aprire posizioni grandi o con leva alta, fino alla liquidazione.

Non può

  • prelevare verso un wallet diverso dal tuo: i prelievi vanno solo al wallet del proprietario dell'account;
  • spostare fondi in un pool pubblico senza la firma del tuo wallet (regola introdotta da Lighter dopo l'incidente).

5. La chiave per le automazioni

Le automazioni che girano a pagina chiusa (trailing, breakeven, take-profit multipli, trade sugli eventi) hanno bisogno di una chiave sul server. Solo se le attivi, affidi al server una seconda chiave dedicata, diversa da quella del browser. È conservata cifrata (AES-256-GCM, con una chiave principale che sta solo nella configurazione del server), è usata solo per le regole che imposti e viene cancellata quando disattivi le automazioni.

6. Consigli

  • Una chiave dedicata a LighterDeck, che non usi altrove: se un'app ha un problema, revochi solo quella.
  • Un sub-account con il solo capitale che vuoi usare, se possibile.
  • Permessi e limiti per chiave: quando Lighter li renderà disponibili, limita la chiave di LighterDeck alle azioni e ai mercati che usi. L'elenco di IP consentiti va bene per una chiave che lavora su un server con IP fisso. Non usarlo per la chiave nel browser: l'IP di casa o del telefono cambia e la chiave smetterebbe di funzionare.
  • Revoca le chiavi che non usi più e ruota quelle di cui non sei sicuro: ne crei una nuova e revochi la vecchia.
  • Tieni aggiornati browser e sistema, e non installare estensioni di cui non ti fidi: possono leggere le pagine che apri.
  • Apri LighterDeck solo da lighterdeck.xyz, o da un'istanza che gestisci tu.

7. Segnalare un problema

Se trovi una vulnerabilità, segnalala in privato con il modulo di GitHub (scheda Security → Report a vulnerability): la vedono solo i maintainer finché non è corretta. Non aprire una issue pubblica e non pubblicare mai chiavi, nemmeno di test. Per tutto il resto usa le issue.

Security

Last updated: 17 November 2026

In short: on lighterdeck.xyz your API key stays in your browser. Orders are signed there with Lighter's official signer and go straight to Lighter. LighterDeck's server never receives the key and never touches your funds.

1. Where the key stays

  • Only in your browser. When you connect an API key, LighterDeck checks it with Lighter directly from the browser and keeps it there. It is not sent to LighterDeck's server or to anyone else.
  • "Remember the key in this browser". When ticked, the key is saved in the browser's storage for this site and you are connected again when you come back. When not ticked, it lasts only while the tab is open. The browser's storage is not encrypted: on a shared computer, or a device you don't trust, leave it unticked.
  • Disconnecting the key in LighterDeck deletes it from the browser. To make it unusable everywhere, revoke it on Lighter's API keys page.

2. How orders are signed

  • LighterDeck uses Lighter's official signer, lighter-go, compiled to WebAssembly without changes. Signed orders go from your browser to Lighter's API.
  • Every signature uses a new random value (the nonce), drawn from the browser's secure random generator. Sign the same order twice and you get two different signatures.
  • The page runs only LighterDeck's own code, served from lighterdeck.xyz: a Content-Security-Policy blocks scripts from other sites and allows connections only to LighterDeck and Lighter. Even if someone managed to inject code into the page, it couldn't send the key anywhere else.
  • LighterDeck's code is open source: anyone can check what it does with the key. The signer is in frontend/signer/, with the lighter-go commit it was built from.
The November 16, 2026 incident. A trader's keys were worked out from their signatures, because their own, unofficial signing code reused nonces. LighterDeck signs only with the official signer, which draws every nonce securely at random, and was not exposed to this problem.

3. Creating a key with your wallet

  • With "Create a key with my wallet" the new key is generated in your browser. The wallet only signs Lighter's message that registers that key on your account ("Register Lighter Account").
  • LighterDeck reads the wallet's address to find the account, but never sees the wallet's private key or recovery phrase. It will never ask for either: if someone asks for them in LighterDeck's name, it's a scam.
  • Only sign messages you recognise in your wallet. Lighter's ends with "Only sign this message for a trusted client!".

4. What an API key can do

Whoever holds it can

  • trade on your account, even against you at bad prices, especially in thin markets;
  • open large or highly leveraged positions, up to liquidation.

It can't

  • withdraw to a wallet other than yours: withdrawals only go to the account owner's wallet;
  • move funds into a public pool without your wallet's signature (a rule Lighter added after the incident).

5. The key for automations

Automations that run with the page closed (trailing, breakeven, scaled take-profits, event trades) need a key on the server. Only if you turn them on, you hand the server a second, dedicated key, separate from the browser's. It is kept encrypted (AES-256-GCM, with a master key held only in the server's configuration), used only for the rules you set, and deleted when you turn automations off.

6. Advice

  • A dedicated key for LighterDeck that you use nowhere else: if one app has a problem, you revoke only that key.
  • A sub-account holding only the capital you want to use, where possible.
  • Per-key permissions and limits: when Lighter makes them available, limit LighterDeck's key to the actions and markets you use. An IP allowlist suits a key working from a server with a fixed IP. Don't use it for the browser's key: your home or phone IP changes and the key would stop working.
  • Revoke keys you no longer use and rotate any you're unsure about: create a new one and revoke the old.
  • Keep your browser and system up to date, and don't install extensions you don't trust: they can read the pages you open.
  • Open LighterDeck only at lighterdeck.xyz, or on an instance you run yourself.

7. Reporting a problem

If you find a vulnerability, report it privately with GitHub's form (Security tab → Report a vulnerability): only the maintainers see it until it's fixed. Don't open a public issue, and never post keys, not even test ones. For everything else, use the issues.
